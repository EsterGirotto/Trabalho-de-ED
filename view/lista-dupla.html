Listas Duplamente Encadeadas

Estrutura em que cada nó aponta para o próximo e para o anterior, permitindo navegação nos dois sentidos.

Conceito

A Lista Duplamente Encadeada também é formada por nós, mas cada nó possui duas referências: uma para o próximo nó e outra para o nó anterior. Por isso, ela consegue caminhar nos dois sentidos.

Essa estrutura é muito útil quando o sistema precisa avançar e voltar entre elementos. Históricos de navegação, playlists, editores de texto, carrosséis e listas ordenadas podem se beneficiar desse tipo de organização.

A principal diferença em relação à lista simples é que cada nó sabe quem vem antes e quem vem depois. Isso facilita algumas remoções e navegações, mas exige mais memória e mais cuidado ao atualizar as ligações.

Exemplo do cotidiano

Pense em uma playlist de músicas. Você pode avançar para a próxima faixa ou voltar para a faixa anterior. Cada música conhece sua vizinha da frente e sua vizinha de trás. Essa é a ideia central de uma lista duplamente encadeada.

null ↔ 8 ↔ 16 ↔ 32 ↔ null
O(1) Inserir no início/fim

Com referências para início e fim, a lista ajusta poucas ligações.

O(n) Buscar valor

Mesmo andando nos dois sentidos, encontrar um valor ainda pode exigir percorrer vários nós.

+mem Custo extra

Cada nó guarda duas referências, aumentando o consumo de memória.

Como acontece uma inserção no fim

  1. Cria-se um novo nó com o valor desejado.
  2. O antigo último nó passa a apontar para o novo nó.
  3. O novo nó aponta de volta para o antigo último nó.
  4. A referência fim é atualizada para o novo nó.

Quando escolher lista dupla

Navegação ida e volta

Boa para playlists, histórico de navegador, galerias e telas com botão próximo/anterior.

Remoção mais prática

Quando você já tem o nó em mãos, pode usar a referência anterior sem procurar desde o início.

Mais cuidado

Cada inserção ou remoção precisa atualizar o ponteiro anterior e o próximo corretamente.

Exemplo em C#

public class NoDuplo
{
    public int Valor;
    public NoDuplo? Anterior;
    public NoDuplo? Proximo;

    public NoDuplo(int valor)
    {
        Valor = valor;
    }
}

public class ListaDupla
{
    private NoDuplo? inicio;
    private NoDuplo? fim;

    public void InserirNoFim(int valor)
    {
        NoDuplo novo = new NoDuplo(valor);

        if (inicio == null)
        {
            inicio = novo;
            fim = novo;
            return;
        }

        fim!.Proximo = novo;
        novo.Anterior = fim;
        fim = novo;
    }
}

Percorrendo de trás para frente

public void ExibirDeTrasParaFrente()
{
    NoDuplo? atual = fim;

    while (atual != null)
    {
        Console.WriteLine(atual.Valor);
        atual = atual.Anterior;
    }
}

Esse método só é possível porque cada nó possui a referência Anterior. Em uma lista simplesmente encadeada, o caminho natural existe apenas para frente.

Remoção em C#

public bool Remover(int valor)
{
    NoDuplo? atual = inicio;

    while (atual != null)
    {
        if (atual.Valor == valor)
        {
            if (atual.Anterior != null)
                atual.Anterior.Proximo = atual.Proximo;
            else
                inicio = atual.Proximo;

            if (atual.Proximo != null)
                atual.Proximo.Anterior = atual.Anterior;
            else
                fim = atual.Anterior;

            return true;
        }

        atual = atual.Proximo;
    }

    return false;
}

Na lista dupla, a remoção precisa religar os dois lados do nó. Se o nó removido for o primeiro ou o último, as referências inicio e fim também mudam.

Erros comuns

  • Atualizar só um lado: se alterar apenas o próximo ou apenas o anterior, a lista fica inconsistente.
  • Esquecer extremos: remover o primeiro ou o último nó exige atualizar inicio ou fim.
  • Não testar lista vazia: operações em lista vazia precisam tratar null antes de acessar campos.
