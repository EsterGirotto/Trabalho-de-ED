TAD - Tipo Abstrato de Dados

Um TAD define quais operações podem ser feitas com um conjunto de dados, escondendo detalhes internos da implementação.

Conceito

TAD significa Tipo Abstrato de Dados. Ele é uma forma de modelar dados e operações sem expor todos os detalhes internos de funcionamento. Em outras palavras, o TAD mostra para o programador quais ações podem ser feitas, mas esconde como essas ações são realizadas por dentro.

A ideia principal é separar interface de implementação. A interface representa os métodos disponíveis, como inserir, remover, buscar ou consultar. A implementação representa a forma como os dados são guardados, por exemplo em vetor, lista encadeada ou objetos ligados por referência.

Esse conceito melhora a organização do programa porque cria um contrato de uso. Quem utiliza o TAD respeita as operações definidas e não altera diretamente os dados internos. Isso reduz erros, facilita manutenção e permite trocar a estrutura interna sem reescrever todo o sistema.

1 Dados

Representam o estado interno do objeto, como valores, contadores, ponteiros ou referências.

2 Operações

Definem o que pode ser feito: inserir, remover, consultar, alterar, limpar ou validar.

3 Regras

Protegem o estado interno para impedir valores inválidos e comportamentos inesperados.

4 Interface

Mostra ao usuário apenas os métodos necessários, escondendo detalhes de implementação.

Exemplo do cotidiano

Pense em um caixa eletrônico. Você escolhe operações como sacar, depositar e consultar saldo. Não precisa saber como o banco valida a transação, atualiza registros ou comunica com o servidor. O caixa oferece uma interface simples e protege os detalhes internos. Um TAD funciona de forma parecida dentro do código.

Como identificar um TAD

  1. Defina quais dados precisam ser armazenados.
  2. Liste quais operações podem ser feitas com esses dados.
  3. Proteja os atributos internos para evitar alterações indevidas.
  4. Ofereça métodos públicos para manipular os dados com segurança.

Por que ajuda?

O código fica menos dependente de detalhes internos. Se a implementação mudar, quem usa o TAD continua chamando os mesmos métodos.

Onde aparece?

Em pilhas, filas, listas, contas bancárias, carrinhos de compra, agendas, jogos e objetos de sistemas reais.

Erro comum

Deixar os atributos públicos demais. Isso quebra o encapsulamento e permite alterações sem passar pelas regras.

Exemplo em C#

public class Pilha
{
    private int[] dados = new int[10];
    private int topo = -1;

    public void Empilhar(int valor)
    {
        if (topo == dados.Length - 1)
            throw new InvalidOperationException("Pilha cheia");

        topo++;
        dados[topo] = valor;
    }

    public int Desempilhar()
    {
        if (topo == -1)
            throw new InvalidOperationException("Pilha vazia");

        int valor = dados[topo];
        topo--;
        return valor;
    }
}

Nesse exemplo, a classe Pilha funciona como um TAD. O usuário chama Empilhar e Desempilhar, mas não manipula diretamente o vetor interno.

Mais um exemplo: Conta Bancária

public class ContaBancaria
{
    private decimal saldo;

    public void Depositar(decimal valor)
    {
        if (valor <= 0)
            throw new ArgumentException("Valor inválido");

        saldo += valor;
    }

    public void Sacar(decimal valor)
    {
        if (valor > saldo)
            throw new InvalidOperationException("Saldo insuficiente");

        saldo -= valor;
    }

    public decimal ConsultarSaldo()
    {
        return saldo;
    }
}

O atributo saldo fica protegido. O acesso acontece somente por operações controladas, como depositar, sacar e consultar. Isso impede que outra parte do sistema defina um saldo negativo sem passar pelas regras da classe.

Resumo para prova

Definição curta

TAD é um conjunto de dados mais operações, definido pelo comportamento e não pelos detalhes internos.

Palavras-chave

Abstração, encapsulamento, interface, implementação, contrato e invariantes.

Exemplos clássicos

Pilha, fila, lista, conjunto, conta bancária, data e agenda de contatos.

Ideia central

O TAD protege os detalhes internos e oferece operações bem definidas.
