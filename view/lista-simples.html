Listas Simplesmente Encadeadas

Estrutura composta por nós, em que cada nó guarda um dado e uma referência para o próximo elemento.

Conceito

Uma Lista Simplesmente Encadeada é uma estrutura formada por nós. Cada nó guarda o dado principal e uma referência para o próximo nó da sequência. O primeiro nó costuma ser chamado de início ou cabeça da lista.

Diferente de um vetor, a lista encadeada não precisa ocupar posições consecutivas na memória. Cada elemento pode estar em uma região diferente, desde que um nó saiba onde está o próximo. Essa ligação é feita por referências.

Ela facilita inserções e remoções no início ou depois de um nó conhecido. Por outro lado, não permite acesso direto por índice como um vetor. Para encontrar um valor, normalmente é preciso começar no primeiro nó e seguir nó por nó.

Exemplo do cotidiano

Imagine uma caça ao tesouro em que cada pista aponta para a próxima pista. Você não consegue ir direto para a terceira pista sem passar pelas anteriores, porque cada uma informa apenas o próximo passo. A lista simplesmente encadeada funciona desse jeito: cada nó sabe apenas quem vem depois.

10 → 25 → 40 → null
O(1) Inserir no início

Basta fazer o novo nó apontar para o antigo início e atualizar a referência da cabeça.

O(n) Buscar valor

Sem acesso por índice, a lista precisa ser percorrida nó por nó até encontrar o item.

O(n) Inserir no fim

Quando não existe uma referência para o último nó, é preciso percorrer a lista inteira.

Operações principais

  1. Inserir no início: o novo nó aponta para o antigo primeiro nó e passa a ser o início.
  2. Inserir no fim: a lista é percorrida até o último nó, que passa a apontar para o novo.
  3. Buscar: começa no início e compara cada valor até encontrar o dado ou chegar em null.
  4. Remover: ajusta a referência do nó anterior para pular o nó removido.

Onde a lista simples faz sentido

Histórico simples

Quando o sistema só precisa avançar em uma sequência, a lista simples evita armazenar referências extras.

Fila de processamento

Itens podem ser conectados dinamicamente, sem exigir um bloco contínuo de memória como em vetores.

Estruturas maiores

Listas encadeadas podem servir de base para pilhas, filas, tabelas hash com colisão e grafos.

Exemplo em C#

public class No
{
    public int Valor;
    public No? Proximo;

    public No(int valor)
    {
        Valor = valor;
        Proximo = null;
    }
}

public class ListaSimples
{
    private No? inicio;

    public void InserirNoInicio(int valor)
    {
        No novo = new No(valor);
        novo.Proximo = inicio;
        inicio = novo;
    }

    public void Exibir()
    {
        No? atual = inicio;

        while (atual != null)
        {
            Console.WriteLine(atual.Valor);
            atual = atual.Proximo;
        }
    }
}

Busca de um valor em C#

public bool Contem(int valor)
{
    No? atual = inicio;

    while (atual != null)
    {
        if (atual.Valor == valor)
            return true;

        atual = atual.Proximo;
    }

    return false;
}

A busca percorre a lista do começo ao fim. Se encontrar o valor, retorna true. Se chegar ao final da lista, representado por null, retorna false.

Remoção em C#

public bool Remover(int valor)
{
    No? atual = inicio;
    No? anterior = null;

    while (atual != null)
    {
        if (atual.Valor == valor)
        {
            if (anterior == null)
                inicio = atual.Proximo;
            else
                anterior.Proximo = atual.Proximo;

            return true;
        }

        anterior = atual;
        atual = atual.Proximo;
    }

    return false;
}

Na remoção, o ponto mais importante é guardar o nó anterior. Sem ele, não há como fazer a lista pular o nó que será removido.

Cuidados que mais caem

  • Lista vazia: antes de acessar o primeiro nó, confira se inicio não é null.
  • Remover o primeiro: nesse caso não existe anterior; a cabeça da lista precisa mudar.
  • Fim da lista: o último nó sempre aponta para null, marcando que não há próximo elemento.

Vantagens e cuidados

  • Inserção no início é simples e rápida.
  • O tamanho pode crescer dinamicamente.
  • O acesso não é direto por índice.
  • A navegação ocorre apenas para frente.
